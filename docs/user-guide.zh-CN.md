# PM Agent OS 使用说明

这份文档是给没有技术背景的人看的。

如果只用一句话来解释，这个系统的作用是：

**把你的工作背景放进固定文档里，而不是放在某一次聊天里。**

这样你就算换 team、换聊天窗口、换模型，AI 也可以接着干，而不用你每次从头解释。

## 先把它想象成什么

你可以把这套系统理解成一个“随身工作档案盒”。

里面主要有四张卡：

1. 个人卡
   记录你是谁、你平时怎么工作、你喜欢什么输出风格。
2. 团队卡
   记录当前 team 做什么、用户是谁、关键指标是什么。
3. 任务卡
   记录你当前这件事的目标、范围和交付物。
4. 交接卡
   记录现在做到哪了、下一步是什么、有什么风险。

AI 每次开始工作前，先看这几张卡，再继续做事。

## 为什么这样做

很多人用 AI 时会遇到同一个问题：

- 开了新对话，前面背景没了
- 换了一个模型，又要重新讲一遍
- 换 team 后，旧上下文不适用了

这个系统就是专门解决这个问题的。

它不依赖“聊天记录记住了多少”，而是依赖你自己的固定文档。

## 你平时到底怎么用

日常其实很简单，只要记住下面这个节奏：

### 第一次建立系统

1. 填好个人卡
2. 填好当前 team 的团队卡
3. 开始工作

### 每做一个较大的任务

1. 建一张任务卡
2. 让 AI 先读取个人卡、团队卡、任务卡
3. 开始输出

### 每次工作结束前

1. 更新交接卡
2. 写清楚“做到哪了、下一步做什么”

这样你下次继续时，就不用重新解释背景。

## 什么时候需要更新哪张卡

### 个人卡

只有在这些情况才需要改：

- 你的角色变了
- 你的工作偏好变了
- 你常用的输出格式变了

它不是每天都要改的。

### 团队卡

在这些情况更新：

- 你换了 team
- team 的重点项目变了
- team 的关键指标变了
- 组织关系和关键协作人变了

### 任务卡

只和当前任务有关。

换任务就换一张。

### 交接卡

这是最常更新的一张卡。

每次做完一段工作，最好都更新。

## 切换 Codex team 后怎么工作

如果你换的是业务 team，而不是只换一个聊天窗口，那最主要要做的是：

1. 保留原来的个人卡
2. 新建或更新新的团队卡
3. 让系统先读取“个人卡 + 新团队卡”

这样 AI 就能理解：

- 你还是同一个人
- 但你现在服务的是新的团队和新的业务

你不需要把旧 team 的全部历史聊天搬过去。

你只需要把当前有效的团队信息写进新的团队卡。

## 切换模型后怎么工作

比如你从 Codex 换到 Kimi，或者从 GPT 换到 Claude。

这时不要想着“把以前所有聊天记录搬过去”，那样很麻烦，也不稳定。

正确做法是：

1. 把当前状态整理成一个 context pack
2. 把这个 context pack 给新的模型
3. 让新模型基于这个状态继续工作

这里的 context pack，本质上就是把几张卡片合成一份最新状态说明。

所以切模型时，搬运的不是历史聊天，而是“当前工作状态”。

## 同平台和跨平台有什么区别

可以直接用一句话理解：

- `Codex / 可读本地文件的工作区`：更接近“自己去读你的工作档案”
- `Claude / Kimi / 千问 / GPT 客户端或网页端`：更接近“你把工作档案递给它”

也就是说：

- 在 Codex 里，通常可以直接读取本地状态文件，所以更适合自动加载和本地回写
- 在其他客户端或网页端里，当前 baseline 默认不能直接读取你电脑上的本地文件
- 它们之所以还能继续工作，是因为你贴入了压缩后的上下文包，不是因为它们自己会去读盘
- 如果你希望这些外部客户端也能直接读文件，需要再接一层 wrapper、本地连接器或类似 MCP 的方案

所以跨平台时，多做的一步不是“重讲一遍历史”，而只是“把最新状态递过去”

## 用户成本最低的用法

如果你追求最低操作成本，不要自己找文件、不要手工拼提示词。

直接用仓库里的脚本，格式统一是：

```bash
cd /Users/wamg/Documents/monthly
./scripts/pm_prompt.py --platform <平台> --mode resume --copy
```

其中 `<平台>` 可以替换成：

- `codex`
- `claude`
- `kimi`
- `qwen`
- `gpt`

这条命令会直接生成并复制一段“可粘贴恢复提示词”到剪贴板。

你只需要：

1. 运行一条命令
2. 打开目标模型
3. 粘贴

收尾时也是同样逻辑：

```bash
cd /Users/wamg/Documents/monthly
./scripts/pm_prompt.py --platform <平台> --mode close --copy
```

区别是：

- `codex + close` 可以直接要求它更新本地文件
- 其他平台一般只能先生成一版 handoff，再由你或 Codex 回写到本地

### 这是不是自动更新

最现实的答案是：

- 同一工作区内，可以做到“半自动”
- 跨平台网页聊天，通常不能真正自动写你电脑上的本地文件

所以最低成本方案不是“完全自动”，而是“一键复制 + 一键粘贴”。

这已经比手工找文件、手工拼上下文稳定得多。

## skill 是什么

可以把 skill 理解成一份“岗位说明书”。

它规定的是 AI 应该怎么工作，比如：

- 先看哪些文件
- 看到什么任务时用哪种角色处理
- 输出时要包含哪些部分
- 做完后要不要更新交接卡

所以：

- 记忆本身在那些卡片文件里
- skill 是让 AI 按固定方法使用这些卡片

## 你最常用的工作姿势

你可以直接把下面这套动作当成默认流程：

### 开始工作时

对 AI 说：

“先读取我的个人卡、团队卡、交接卡，再继续这件事。”

### 做新任务时

对 AI 说：

“先读取个人卡、团队卡和这张任务卡，再开始。”

### 结束工作时

对 AI 说：

“帮我更新交接卡，写清楚当前状态、下一步和风险。”

## 一个最简单的例子

比如你今天在做一个新功能需求。

开始时：

- AI 先看个人卡
- 再看团队卡
- 再看当前任务卡

它就知道：

- 你是怎样的产品经理
- 这个 team 在做什么产品
- 当前这个需求的目标是什么

做完一轮后：

- 它再帮你更新交接卡

明天你回来，或者换另一个模型继续时，只要先看交接卡，就知道上次停在哪。

## 这套系统最大的价值

不是让 AI 变得更聪明。

而是让你的工作连续性不再依赖某个聊天窗口。

你以后真正依赖的，不是“这个模型记不记得你”，而是“你的状态文件是不是完整”。

## 你现在应该先做什么

如果你现在就要开始用，最推荐的顺序是：

1. 先填写个人卡
2. 再填写当前 team 的团队卡
3. 开一个真实任务，写一张任务卡
4. 完成后更新交接卡
5. 第二天故意开一个新会话，测试能不能无缝续接

只要这一步能跑通，后面换 team、换模型都只是换卡片，不是从头再来。
